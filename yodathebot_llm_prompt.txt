# YodaTheBot: WhatsApp AI Chatbot - Comprehensive Project Understanding

You are analyzing a Node.js-based WhatsApp chatbot called "YodaTheBot" that combines AI-powered conversations with user management and multimedia functionality. This document provides a complete understanding of the project's architecture, features, and technical implementation.

## Core Architecture

YodaTheBot follows a modular architecture with these key components:

1. **WhatsApp Integration Layer** (`whatsapp/` directory)
   - Manages WhatsApp connection using WhatsApp Web.js library
   - Handles authentication via QR code scanning
   - Processes incoming and outgoing messages
   - Manages client lifecycle (initialization, events, shutdown)

2. **Bot Logic Layer** (`bot/` directory)
   - Processes all message content
   - Handles user registration flow
   - Verifies and executes commands
   - Integrates with Groq AI for natural language responses

3. **Server Layer** (`server/` directory)
   - Express-based REST API
   - Provides health check endpoints
   - Offers status monitoring
   - Handles HTTP requests and responses

4. **Data Layer** (`models/` directory)
   - MongoDB schemas for data persistence
   - User profile management
   - Chat history storage

5. **Configuration Layer** (`config/` directory)
   - Centralized settings
   - Command definitions
   - Field validation rules
   - Logging configuration

## Detailed Feature Explanation

### 1. User Registration System

The bot implements a sophisticated multi-step registration process:

- **Flow**: When a new user messages the bot, it initiates registration by asking for information sequentially: firstName, lastName, email, college, and date of birth
- **Validation**: Each field has specific validation rules defined in `config/config.js`:
  - `firstName`: Must be 2-25 alphabetic characters
  - `lastName`: Must be 2-25 alphabetic characters
  - `email`: Must match standard email pattern
  - `college`: Any text is accepted
  - `dob`: Must be in dd/mm/yyyy format and a valid date
- **Confirmation**: After each field entry, the bot asks for confirmation ("yes"/"no")
- **Storage**: User data is stored in MongoDB using the User schema
- **Completion**: Once all fields are completed, user's `profile_completed` flag is set to true

### 2. Command System

The bot supports a custom command system defined in `config/config.js`:

- **Command Format**: Commands start with a predefined character (default: "!") followed by the command name
- **Current Commands**:
  - `hi`: Simple greeting function that responds with a friendly message
  - `yt-audio`: Downloads and extracts audio from YouTube videos
  - `ytdl`: Downloads YouTube videos
  - `dl`: Downloads videos from various links

- **Command Structure**: Each command has:
  - `hidden`: Boolean indicating if command should be shown in help
  - `isGroupOnly`: Boolean indicating if command works only in groups
  - `description`: Human-readable description of the command
  - `exec`: Function that executes when command is triggered

- **Command Processing**: When a message arrives, it's passed through:
  1. `commandVerifier.js` to extract the command and arguments
  2. Command is checked against the commands object
  3. If valid, the command's exec function is executed with message and arguments

### 3. AI Conversation

For non-command messages, the bot leverages Groq's AI models:

- **Model**: Uses Mixtral-8x7b-32768 by default
- **Parameters**:
  - Temperature: 0.7 (controls randomness)
  - Max tokens: 1024 (limits response length)
  - Top-p: 1 (controls diversity of responses)
- **Conversation Memory**: Previous messages are stored in MongoDB and included in the context for the AI
- **Message Format**: The AI receives messages in a standard chat format with alternating "user" and "assistant" roles

### 4. Logging System

The bot implements a comprehensive logging system using Winston:

- **Log Levels**: Supports error, warn, info, and debug levels
- **File Rotation**: Logs are automatically rotated when they reach 5MB
- **Storage**: 
  - `logs/error.log`: Contains only error-level entries
  - `logs/combined.log`: Contains all log entries
- **Format**: JSON format with timestamps, service name, and contextual information

### 5. Express API

The bot exposes a RESTful API with these endpoints:

- `GET /health`: Returns server status and timestamp
- `GET /`: Returns general information about the bot
- `GET /status`: Returns current WhatsApp connection status

## Database Schema

### User Model (`models/User.js`)
```javascript
{
  w_id: String,                 // WhatsApp ID (required, unique)
  firstName: String,            // User's first name
  lastName: String,             // User's last name
  email: String,                // User's email
  college: String,              // User's college
  phoneNumber: String,          // Phone number from WhatsApp
  dob: Date,                    // Date of birth
  profile_completed: Boolean,   // Whether registration is complete
  active_field: String,         // Current field in registration
  field_confirmation_state: String, // "asked" or "confirmation"
  chats: [ObjectId],            // References to Chat documents
  createdAt: Date               // User creation timestamp
}
```

### Chat Model (`models/Chat.js`)
```javascript
{
  user: ObjectId,               // Reference to User
  messages: [{                  // Array of messages
    role: String,               // "user" or "assistant"
    content: String             // Message content
  }],
  createdAt: Date               // Chat creation timestamp
}
```

## Technical Implementation Details

### WhatsApp Connection

- **Client Creation**: Uses LocalAuth strategy for persistent sessions
- **Authentication**: Generates QR code that must be scanned with WhatsApp
- **Event Handling**:
  - `authenticated`: When session is authenticated
  - `auth_failure`: When authentication fails
  - `ready`: When client is ready to send/receive messages
  - `qr`: When a new QR code is generated
  - `message`: When a new message is received

### Message Processing Pipeline

1. Message is received through WhatsApp Web.js
2. Bot checks if sender is a new user, existing user with incomplete profile, or regular user
3. For new users, registration flow is initiated
4. For existing users with incomplete profiles, registration continues
5. For regular users:
   - Message is checked for commands
   - If it's a command, the command is executed
   - If not, the message is sent to the AI for processing
6. Response is sent back through WhatsApp

### Error Handling

- Try/catch blocks around critical operations
- Errors are logged with stack traces and context
- Graceful degradation when components fail
- Server has error middleware for API requests
- SIGINT handler for clean shutdown
